# VPlayer 一页纸操作手册

> 日常只需要记这几个命令。发版流程见下方"发版流程"。

## 常用命令

| 命令 | 作用 |
|------|------|
| `npm run dev` | 前端热更新（仅渲染层） |
| `npm run electron:dev` | 起 Electron 调试（先 build 前端） |
| `npm run build` | 构建前端到 dist |
| `npm run smoke` | 冒烟测试（L1 静态 → L2 逻辑 → L4 Electron 集成） |
| `npm run status` | 查看问题清单与项目状态 |
| `npm run verify` | 发版前体检（冒烟 + 台账 + 版本） |
| `npm run handoff` | 生成交接指令包 |
| `npm run electron:build` | 构建 Linux deb + 编解码组件 |
| `npm run electron:build:win` | 构建 Windows NSIS（在 Windows 上） |

## 开发要点

- 冒烟 `npm run smoke` 必须全通过（允许 ⚠，不允许 ✗）才可提交/发版。
- 用户可见文案走 `src/i18n/index.js` 的 `t(key)`，**不要硬编码中英文**。
- 改架构前读 `docs/STATE.md`；问题登记/更新在 `docs/TASKS.md`。
- 依赖保持轻量：能原生/零依赖解决就不引第三方包。

## 发版流程

1. `npm run verify` —— 确认无阻塞项（🔴 高优清零、冒烟全过、无同版本 tag）。
2. bump `package.json` 与 `package-lock.json` 版本一致。
3. 写审查请求放工作空间根目录，交第三方智能体（workbuddy）审查 → 按结论修复 → 确认。
4. 本地 `npm run electron:build` 预构建验证。
5. 推 `master` 试构建 → 推与 package.json 版本一致的 `v*` tag → GitHub Actions 产出三平台安装包 + 各平台编解码组件 zip 挂到 Release。

## 平台差异提醒

- **Linux**：`--no-sandbox` 由 .desktop executableArgs 与 postinst（chrome-sandbox SUID）处理。
- **macOS**：CI 由 icon.png 生成 icns；afterPack 做 ad-hoc 重签。
- **Windows**：差量升级走 electron-updater blockmap；NSIS 安装器。

## 冒烟分层

`node scripts/smoke/run.mjs --layer L1` 等，或 `--skip L4`。L4 需显示环境（Linux CI 用 xvfb-run）。
